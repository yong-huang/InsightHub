The Operator Pattern

Automating complex operational tasks in Kubernetes using custom controllers. The standard way to manage applications and infrastructure.

Scene 01

What is an Operator?

Extending Kubernetes for application-specific automation

👤 Manual Operations

"Human intervention for every action"

human-ops.sh
# Human must handle everything kubectl apply -f deployment.yaml # Wait for pods to be ready... kubectl rollout restart deployment/app # Check if rollback needed... kubectl scale deployment/app --replicas=5 # Database backup? Manual script. ./backup-database.sh
Problem: Humans make mistakes, forget steps, and can't respond 24/7. Each application needs unique operational knowledge.

🤖 Kubernetes Operator

"Application-specific controller encoded in software"

Database.yaml
apiVersion: example.com/v1 kind: Database metadata: name: my-db spec: version: "14.0" replicas: 3 backupSchedule: "0 2 * * *" storage: 100Gi
Solution: Operator knows HOW to achieve desired state. It handles upgrades, backups, scaling, and failures automatically.

An Operator is a custom Kubernetes controller that encodes operational knowledge for a specific application. It extends Kubernetes to manage stateful applications like databases, message queues, and caching systems.

Scene 02

The Controller Pattern

The foundation of Kubernetes automation

👁️ Watch

Controller continuously watches API server for changes to resources it's responsible for.

🔄 Reconcile

Compare desired state (from YAML) with actual state (from cluster) and take action to align them.

⚡ Act

Create, update, or delete resources to achieve desired state. Create pods, services, configmaps, etc.

Kubernetes Built-in Controllers

🎯

Deployment Controller

Manages ReplicaSets and Pods for stateless applications. Handles rolling updates and rollbacks.

🔑

Service Controller

Creates load balancers and configures proxy rules for service discovery.

📋

Namespace Controller

Manages namespace lifecycle and cleanup of resources in deleted namespaces.

Custom Controllers = Operators

operator-vs-controller
# Built-in Deployment Controller apiVersion: apps/v1 kind: Deployment # Works for any stateless app spec: replicas: 3 # Custom Database Operator apiVersion: example.com/v1 kind: Database # Knows PostgreSQL specifics spec: version: "14.0" # Handles upgrades backupSchedule: "daily" # Runs pg_dump
Scene 03

Custom Resource Definitions

Extending the Kubernetes API

CRDs define new kinds of resources. Once installed, you can use kubectl to manage them just like built-in resources.

📄 CRD Definition

database-crd.yaml
apiVersion: apiextensions.k8s.io/v1 kind: CustomResourceDefinition metadata: name: databases.example.com spec: group: example.com versions: - name: v1 served: true storage: true scope: Namespaced names: plural: databases singular: database kind: Database shortNames: - db

🚀 Using the Custom Resource

my-database.yaml
apiVersion: example.com/v1 kind: Database metadata: name: my-postgres spec: version: "14.0" replicas: 3 storage: 100Gi backupSchedule: "0 2 * * *"
terminal
# Apply the custom resource kubectl apply -f my-database.yaml # List all databases kubectl get databases # Get details kubectl get db my-postgres -o yaml

📋 CRD Schema Validation

version string (required)
replicas integer (1-10)
storage quantity (e.g., "100Gi")
backupSchedule cron expression
enableSSL boolean (default: true)
Scene 04

The Reconciliation Loop

How Operators maintain desired state continuously

👁️ Watch

Monitor CRDs and related resources

📥 Fetch

Get current cluster state

⚖️ Compare

Desired vs Actual state

⚡ Act

Update resources to match

🔄 Continuous Reconciliation

reconcile.go
func (r *DatabaseReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) { // 1. Fetch the Database resource db := &Database{} if err := r.Get(ctx, req.NamespacedName, db); err != nil { return ctrl.Result{}, err } // 2. Check current state deployment := &appsv1.Deployment{} r.Get(ctx, client.ObjectKey{Name: db.Name}, deployment) // 3. Compare and reconcile if deployment.Spec.Replicas != db.Spec.Replicas { deployment.Spec.Replicas = db.Spec.Replicas r.Update(ctx, deployment) } // 4. Requeue for next check return ctrl.Result{RequeueAfter: time.Minute * 5}, nil }

🎯 Triggers Reconciliation

📝 CRD Change

User updates Database spec

🔄 Resource Change

Pod crashes or updates

⏰ Periodic

Regular health checks

🎬 Manual Request

kubectl annotate with reconcile

Key Takeaways

Why Operators Matter

🔄 Encode Operational Knowledge

Operators capture human expertise in code. No more runbooks, tribal knowledge, or manual procedures.

⚡ Self-Healing Systems

Operators continuously reconcile state. When things break, they automatically fix them without human intervention.

🎯 Declarative Management

Describe WHAT you want, not HOW. The Operator figures out the implementation details.

🌐 Native Kubernetes Integration

Operators use standard Kubernetes patterns. They work with kubectl, Helm, and GitOps workflows.

🔧 Extensible Platform

CRDs let you extend Kubernetes for any application. The cluster becomes your automation platform.

🏭 Production Ready

Major cloud providers and enterprises use operators to manage databases, messaging, and data infrastructure.
